# RG-01 production lifecycle verification

Issue [#83](https://github.com/gearstack-studio/kitloop/issues/83) delivers the lifecycle recovery prerequisite for [#85](https://github.com/gearstack-studio/kitloop/issues/85). DEV4952 owns execution and yiiipunn verifies the production result. Use the existing [lifecycle release and reconciliation runbook](REQUEST-LIFECYCLE-ROLLOUT.md) and [OD-13](../../docs/labs/lab-07/CR-01-impact-analysis.md#205-deployment-procedure-od-13-agreed-2026-11-26-2148-ict-flag-authorization-pending).

## Preflight and deploy

1. Record the dated team authorization and chosen configuration-only redeploy path in #83. OD-13 requires explicit team authorization before enabling `LAB5_DEPLOY_ENABLED`. The protected workflow requires yiiipunn to merge the reviewed release PR and DEV4952 to approve the `lab5-production` deployment. A config-only change has no workflow trigger. For the documented same-SHA manual path, record team agreement and have DEV4952 run the existing release command.
2. Record the backup, Cloud Run revision receiving 100% traffic, its image digest, `REQUEST_LIFECYCLE_WRITES`, and `GET /api/version` full SHA. Compare GitHub environment variables with effective configuration on the serving revision. Verify `features.requestLifecycleActions: false` by signing in with an authorized synthetic account. Phase 1 must be serving the same SHA and digest planned for phase 2.
3. Enable lifecycle writes while keeping borrowing quota disabled. On the approved manual path, use `KITLOOP_REQUEST_LIFECYCLE_WRITES=enabled KITLOOP_BORROWING_QUOTA=disabled bash infra/gcp/release.sh deploy "$PHASE1_SHA"`. Coordinate the matching GitHub environment variables before any later automated rollout.
4. Record the new serving revision and verify the SHA and digest still match phase 1, readiness is healthy, and the signed-in feature reports `requestLifecycleActions: true`.

Stop before activation if the team authorization, approved path, authenticated revision readback, same-SHA image digest, or synthetic fixtures are missing. A later reviewed merge can establish a new phase-1 revision. If its SHA differs, first verify that revision with writes disabled, then use its SHA and digest for phase 2. Record the chosen phase-1 rollback target before shifting traffic.

## Verify with synthetic fixtures

Use authorized synthetic borrowers, an assigned custodian, an unassigned custodian, and disposable assets. Record the ICT date, serving revision, synthetic request IDs, actor role, HTTP status, and before/after readback. Keep session cookies and CSRF tokens out of the evidence.

| Scenario | Intended result |
| --- | --- |
| Another borrower attempts cancel, then the owner checks the row | 404 and still PENDING |
| The owner cancels their own PENDING request | 200 and CANCELLED, closure recorded |
| An unassigned custodian attempts decline, then the owner checks the row | 404 and still PENDING |
| The assigned custodian declines the PENDING request with a valid reason | 200 and DECLINED, closure recorded |
| The assigned custodian checks out one of two competing requests | 201 and winner CHECKED_OUT, competitor DECLINED with `ASSET_CHECKED_OUT_TO_ANOTHER_BORROWER` |
| Missing CSRF on a lifecycle action | 403 and readback unchanged |

Run the reviewed Cloud Run reconciliation job while phase 2 serves. Retain the dry-run JSON and review the affected records and scope before executing apply with the confirmed database name. Use the same approved scope for dry run, apply, and the final dry run. Stop if the target database, image, scope, or affected records differ from the approved plan. Retain the job execution IDs, exit status and JSON. A passing rerun reports `staleOnActiveLoan: 0` and no conflicts. Delete the one-off job after verification. Keep production JSON containing real borrower identifiers in restricted release evidence and link the sanitized summary from #85.

## Rollback

Disable borrowing quota and lifecycle writes together for a same-SHA compatibility redeploy. Use `KITLOOP_BORROWING_QUOTA=disabled KITLOOP_REQUEST_LIFECYCLE_WRITES=disabled bash infra/gcp/release.sh deploy "$PHASE1_SHA"` after approval, or use the recorded ready phase-1 revision with quota and lifecycle writes disabled. Keep lifecycle history readable, verify the active revision, readiness and signed-in feature flags after rollback, and follow the rollout runbook for reachable phase-2 tags and one-off jobs.
